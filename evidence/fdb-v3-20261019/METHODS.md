# Evaluation methods and provenance

- Version A reuses the 100 saved released-v9 results in evidence/released-v9/report.json. Its historical strict score remains 77/100. Original inference was not replayed, and the original evidence is preserved.
- Version B runs the current repaired controller through the existing streaming LiveKit benchmark with gemini-3.8-live, guarded policy, the same released dataset, seed, tool definitions, settlement settings and concurrency of two. Only FDB mock tools execute; Google Workspace mutations are disabled.
- The completed first live pilot was reused when changing judges. reused-voice-pilot-provenance.json records the copied result hash and verifies that only evaluation labeling changed after that recording; controller and agent behavior did not change.
- Initial gemma-4-31b-it argument judging succeeded, but response judging repeatedly returned HTTP 500. The user then authorized alternative semantic models. available-judge-models.json contains the complete 63-model API listing for the judge project. gemma-4-26b-a4b-it passed both argument and response verification and is used consistently for both versions. The earlier 31B judgments and diagnostics remain separate and are not included in 26B scores.
- Semantic judgments retain the pinned upstream FDB-v3 argument and response prompts and evaluation rules. The generation settings for both versions are identical: temperature 0, minimal thinking, maximum output 200 tokens for arguments/responses. Parsing requires a JSON boolean correct and string explanation; fenced JSON is accepted. There is no fallback to exact matching.
- Strict pass uses the pinned upstream exact tool scorer. Semantic tool pass requires exact tool selection and semantically correct expected-call arguments, with confirmed successful execution and no infrastructure error. Spoken-response correctness is reported separately, as in the upstream tool evaluator; it is not silently folded into tool pass rate.
- Tool precision, recall and F1 and strict argument accuracy come from the pinned upstream tool evaluator. Semantic argument matching follows upstream expected/actual pairing by function and order. Missing expected calls receive argument score zero without a judge request. Extra calls affect selection/pass rate. Judgments that fail remain unresolved and never become exact-match judgments.
- Both workloads share one serial judge queue, one cache, and one rolling rate budget (28 RPM and 14,000 conservatively reserved input-plus-maximum-output tokens per minute). Both use GOOGLE_API_KEY_2; voice uses GOOGLE_API_KEY. Secrets are not exported.
- Judge calls retry transient HTTP 429/500/502/503/504 and connection failures at most four attempts, with exponential backoff, jitter, and Retry-After. Persistent failures pause both workloads. Successful judgments and completed inference are reused on resume.
- Provider output transcriptions are used for response judging. Version A has three missing transcripts; the upstream response criterion assigns zero to unavailable transcripts. Those are distinguished from failed judge requests. These transcripts are not independently transcribed from saved audio.
- Latency reports include only observed tool/controller/SDK timing. Tool execution uses FDB mocks. No independent timestamped ASR/shared input-output audio clock is available, so official aligned audio-response and task-completion latencies remain unavailable.
- Superseded proposals, validation rejections and stale-result suppressions are reported from current traces, with raw events retained. Historical controller trace counts are unknown when no trace exists. Argument-error counts in case-outcomes.csv exclude missing-tool entries, which have their own column.
- Historical A and fresh B voice inference are nondeterministic. Observed score/case differences do not by themselves establish controller causation. The earlier hardened 69/100 run is a separate preserved artifact and is not Version B.

Reports and checkpoints are updated during the run. An incomplete semantic pass fraction is not a final semantic score.
